# 测试机对码与换机方案

## 目标

生产线测试机只有 LEDM 和按键，没有 LCDM，所以测试机端不承担菜单设置。打印驱动端带 LCDM，作为本线 AT32 打印主机，负责对码、绑定工位、下发参数和保存本线绑定表。

本方案用于开线、增加测试机、替换故障测试机。操作员只需要让需要对码的测试机进入对码模式，再在本线打印主机 LCDM 上确认绑定。MAS 在线时同步绑定结果；MAS 离线时不影响换机，打印主机先本地保存，恢复后补传。

## 角色

| 角色 | 功能 |
|---|---|
| 测试机分机 | IO 扫描、学习缓存、测试结果、LEDM 状态显示、按键进入对码 |
| AT32 打印主机 | 本线 AP 下的 AT32 + LCDM 人机界面、工位绑定表、产品/线序资料、标签模板、打印机参数、生产记录、本线缓存、MAS 同步 |
| Zebra 打印机 | 只负责接收 ZPL/串口数据并打印，不负责对码管理 |
| MAS | 保存全车间最终绑定表、历史追溯和统计；不作为本线换机的实时必需条件 |

## 基本原则

| 项目 | 规则 |
|---|---|
| 工位归属 | 由本线打印主机绑定和保存，再同步 MAS |
| 测试机身份 | 使用 MCU UID、无线 MAC 或其它唯一 ID |
| 测试机本地设置 | 不通过 LCDM 设置，只通过按键进入对码 |
| 换机 | 新机器进入对码后，由主机绑定到原工位并下发原资料 |
| 产品资料 | 以打印主机保存为主，测试机只保留当前使用缓存 |
| MAS 离线 | 允许换机；打印主机本地记录 `binding_event`，恢复后补传 |
| 冲突处理 | 同一 `STxx` 只能有一个 active 设备；替换后旧设备标记 inactive/removed |

## 测试机进入对码

测试机按键定义：

| 操作 | 功能 |
|---|---|
| `K1 自检 + K4 确认` 长按约 2 秒 | 进入对码模式 |
| `K3 复位/重来` | 退出对码或回到待机 |
| `K4 确认` | 后续可作为本机确认键，但不负责选择工位 |

进入对码后，测试机 LEDM 交替显示：

```text
PAIR
xxxx
```

其中 `xxxx` 是设备唯一 ID 的短码，例如 UID 或 MAC 后 4 位，方便现场人员在 LCDM 列表中核对。

## 打印主机 LCDM 对码

LCDM 增加 `设备对码` 菜单。主机进入该页面后，监听正在申请对码的测试机。

页面建议显示：

| 显示项 | 内容 |
|---|---|
| 设备短码 | UID/MAC 后 4 位 |
| 原工位 | 未绑定、或原 `ST01`-`ST10` |
| 信号/在线 | 最近收到申请的时间或在线状态 |
| 操作 | 绑定新工位、替换已有工位、取消 |

主机操作流程：

1. 测试机长按 `K1+K4` 进入对码，LEDM 显示 `PAIR/xxxx`。
2. LCDM 进入 `设备对码`。
3. 主机列表显示申请对码的设备短码。
4. 操作员点选设备。
5. 选择 `绑定 STxx` 或 `替换 STxx`。
6. 主机下发线体号、工位号、当前产品线序资料和打印规则。
7. 测试机保存成功后回 `PAIR_ACK`。
8. 测试机 LEDM 显示 `P-xx`，随后显示 `LOAD/RDY` 或直接回待机。

当前 WiFi/MAS 架构下，实际通讯路径为：

```text
新测试机 -> 本线 AP -> 本线 AT32 打印主机 -> 本地绑定表
                                             |
                                             +-> MAS 同步
```

不是：

```text
新测试机 -> MAS -> 打印主机
```

因此 MAS 或上级网络断线时，本线仍然可以完成换机和继续生产。

换机时，原 `STxx` 的产品资料、线序 profile、测试规则和打印规则都由本线 AT32 打印主机下发给新测试机。MAS 在线时只负责同步记录；MAS 离线时不阻塞换机。

## 换机流程

以 `ST03` 故障为例：

1. 拆下旧测试机，装上新测试机。
2. 新测试机上电。
3. 长按 `K1+K4` 约 2 秒，进入对码，LEDM 显示 `PAIR/xxxx`。
4. 打印主机 LCDM 进入 `设备对码`。
5. 点选新设备短码。
6. 选择 `替换 ST03`。
7. 主机把原 `ST03` 的产品资料、学习线序和打印规则下发给新测试机。
8. 新测试机保存后显示 `P-03`。
9. 打印主机把原设备 `device_uid_old` 标记为 inactive，把新设备 `device_uid_new` 标记为 `L01/ST03 active`。
10. 打印主机保存 `binding_event` 到本地缓存；MAS 在线则立即上传，MAS 离线则恢复后补传。
11. 替换完成，新测试机可直接按原 `ST03` 资料继续生产。

此流程不要求测试机重新学习整套产品资料。

## 绑定表和缓存

打印主机本地必须保存一份权威的本线绑定表，至少包含：

| 字段 | 说明 |
|---|---|
| `line_id` | 生产拉，例如 `L01` |
| `station_id` | `ST01` ... `ST10` |
| `device_uid` | 当前绑定测试机唯一 ID |
| `device_short_code` | LCDM/LEDM 显示短码 |
| `active` | 当前是否有效 |
| `profile_id` / `profile_rev` | 当前产品/线序资料版本 |
| `assigned_at` | 绑定时间 |
| `assigned_by` | 操作员或本地主机账号 |
| `sync_state` | `SYNCED` / `PENDING` / `FAILED` |

换机事件也要保存：

| 字段 | 说明 |
|---|---|
| `binding_event_id` | 本线递增事件号，用于 MAS 去重 |
| `action` | `bind_new` / `replace` / `remove` |
| `old_device_uid` | 被替换设备，可为空 |
| `new_device_uid` | 新设备 |
| `station_id` | 被绑定的工位 |
| `profile_rev` | 下发给新设备的资料版本 |
| `result` | 成功/失败和错误码 |

缓存位置建议：

| 位置 | 职责 |
|---|---|
| AT32 打印主机 | 保存本线绑定表、换机事件、产品资料、打印队列，是主要缓存位置 |
| 测试机 | 只保存自己的 `device_uid`、当前 `line_id/station_id`、当前 profile 缓存和少量待确认事件 |
| MAS | 保存全车间最终记录和长期历史，恢复联网后由打印主机补传 |

## 建议通讯命令

第一版只需要实现以下命令：

| 命令 | 方向 | 内容 |
|---|---|---|
| `PAIR_REQ` | 测试机 -> 主机 | 唯一 ID、短码、固件版本、原工位 |
| `PAIR_ASSIGN` | 主机 -> 测试机 | Line ID、Station ID、产品 ID |
| `PROFILE_PUSH` | 主机 -> 测试机 | 当前产品线序资料、阈值、测试规则 |
| `PAIR_ACK` | 测试机 -> 主机 | 保存成功/失败、当前 Station |
| `PAIR_CANCEL` | 主机 -> 测试机 | 取消对码 |
| `BINDING_SYNC` | AT32 主机 -> MAS | 绑定/换机事件，本地成功后异步上传 |
| `BINDING_SYNC_ACK` | MAS -> AT32 主机 | MAS 已保存绑定事件 |
| `HEARTBEAT` | 双向 | 在线状态、当前模式、错误码 |

后续打印业务再使用：

| 命令 | 方向 | 内容 |
|---|---|---|
| `RESULT_UPLOAD` | 测试机 -> 主机 | Station、PASS/NG、错误点、测试次数 |
| `PRINT_REQUEST` | 测试机 -> 主机 | 到达打印位置，需要按当前结果打印 |
| `PRINT_ACK` | 主机 -> 测试机 | 已接收/忙/打印完成/错误 |

## LEDM 状态建议

| 显示 | 意义 |
|---|---|
| `PAIR` | 正在申请对码 |
| `xxxx` | 设备短码 |
| `P-01` ... `P-10` | 已绑定工位 |
| `LOAD` | 正在接收资料 |
| `RDY` | 对码完成，可正常测试 |
| `OFFL` | 主机离线或通讯失败 |
| `FAIL` | 对码或保存失败 |

## 实现顺序

1. 在测试机固件增加 `K1+K4` 长按进入对码模式。
2. 在通讯层增加 `PAIR_REQ` 周期发送。
3. 在打印主机 LCDM 增加 `设备对码` 页面和设备列表。
4. 主机保存 `Line/Station/Device ID` 绑定表。
5. 增加 `PAIR_ASSIGN` 和 `PAIR_ACK`。
6. 增加 `PROFILE_PUSH`，用于换机后自动恢复原工位资料。
7. 增加本地 `binding_event` 缓存和 `BINDING_SYNC` 补传。
8. 再接入 `RESULT_UPLOAD` 和 `PRINT_REQUEST` 的正式生产通讯。
